Search & Inclusion Flow ​

A person is not in your system. You look for their household in SIMAST with a Person Search, then ask SIMAST to include that household in one of your requests with Extend a Request.

Steps ​

  1. Create the search — Create search. Keep the search uuid: every result, including those decided later by an analyst, arrives under it.
  2. Get the result — the search.updated webhook, or Search items.
  3. REVISION — a SIMAST analyst reviews the person. Wait for the next search.updated on the same search; don't create a new one.
  4. NO_MATCH — with DONNEES_INSUFFISANTES or DOUBLON_AMBIGU, send the person again with more data (birth date, NINU, phone) in a sub-search. With ABSENTE_DU_REGISTRE, the person is not in the registry.
  5. MATCH — check the person's identity against the household from Search data.
  6. Request inclusion — Extend a Request on the root uuid of the chosen request. The household is checked against that request's criteria and zones. Keep data.id: it identifies the inclusion.
  7. Wait for processing — processing is asynchronous; wait for the demande.* webhook. If the inclusion failed, reprocess it with data.id.
  8. Read the result — details[].include in the webhook or in List requests.
  9. Eligible — Get Data List with data.id returns this household only.
  10. Return Url — the household is then part of the chosen request's Return Url, with its SIMAST code.
