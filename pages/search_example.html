Search Example ​

A complaint desk has received complaints from 3 persons and needs to know which households they belong to. The households of the activity were delivered earlier through a data request.

1. Create the search ​

Send the persons with your own reference (here, the complaint number).

js
const { data } = await axios.post('BASE_URL/v1/third-app/activities/activity:uuid/searches', {
  name: 'Complaints September',
  persons: [
    { external_ref: 'PL-001', nom: 'JEAN', prenom: 'PIERRE', sexe: 1, date_naissance: '1980-05-12' },
    { external_ref: 'PL-002', nom: 'JOSPEH', prenom: 'MARIE' },          // typo in the name
    { external_ref: 'PL-003', nom: 'LOUIS', prenom: 'ANNE' }
  ]
});
const searchUuid = data.data.uuid;   // 202, status PENDING

2. Receive the webhook ​

When the automatic processing ends, SIMAST sends search.updated to your callback_url (verify the signature):

json
{
  "event": "search.updated",
  "data": {
    "id": "0cb5ca49-5f7b-427e-bb13-0f94c1121973",
    "status": "COMPLETED",
    "search": { "id": "0cb5ca49-5f7b-427e-bb13-0f94c1121973", "status": "COMPLETED" },
    "summary": { "total": 3, "match": 2, "revision": 1, "no_match": 0 },
    "items": [
      { "id": "5f0c7a52-…", "external_ref": "PL-001", "status": "MATCH", "menage_code": "0001-00001", "membre_rang": 1, "menage_version": 2025, "reason": null },
      { "id": "8d2a4c61-…", "external_ref": "PL-002", "status": "MATCH", "menage_code": "0001-00417", "membre_rang": 3, "menage_version": 2025, "reason": null },
      { "id": "9b3e2f10-…", "external_ref": "PL-003", "status": "REVISION", "menage_code": null, "membre_rang": null, "menage_version": null, "reason": null }
    ]
  }
}

PL-001 and PL-002 are found, despite the typo. PL-003 is sent to a SIMAST analyst.

3. Read the results ​

js
// Persons: link each complaint to its household
const items = await axios.get(`BASE_URL/v1/third-app/searches/${searchUuid}/items`, { params: { status: 'MATCH' } });
// items.data.data[0] → { external_ref: 'PL-001', menage_code: '0001-00001', membre_rang: 1, menage_version: 2025, … }

// Households of the MATCH, fixed set of fields
const households = await axios.get(`BASE_URL/v1/third-app/searches/${searchUuid}/data`);
// households.data.data[0] → { code: '0001-00001', version: 2025, commune: '111', chef_nom: '…', telephone_1: '…', membres: [ … ] }

// The person of complaint PL-001: compare with the ID card they present
const item = items.data.data[0];
const household = households.data.data.find((h) => h.code === item.menage_code);
const person = household.membres.find((m) => m.rang === item.membre_rang);   // { nom, prenom, ninu, lien_chef, … }

4. After the analyst review ​

The analyst decides PL-003. You receive a new search.updated with only the persons decided in that review session:

json
{
  "event": "search.updated",
  "data": {
    "id": "0cb5ca49-5f7b-427e-bb13-0f94c1121973",
    "status": "COMPLETED",
    "search": null,
    "summary": { "total": 3, "match": 2, "revision": 0, "no_match": 1 },
    "items": [
      { "id": "9b3e2f10-…", "external_ref": "PL-003", "status": "NO_MATCH", "menage_code": null, "membre_rang": null, "menage_version": null, "reason": "DONNEES_INSUFFISANTES" }
    ]
  }
}

DONNEES_INSUFFISANTES: the complaint desk collects the birth date of PL-003 and sends it again.

5. Send the person again in a sub-search ​

js
await axios.post(`BASE_URL/v1/third-app/searches/${searchUuid}/searches`, {
  persons: [{ external_ref: 'PL-003', nom: 'LOUIS', prenom: 'ANNE', date_naissance: '1975-03-02' }]
});

The sub-search uses the same scope. Its results are included in the root search: keep reading /searches/{searchUuid}/items and /data with the root uuid.

6. Get the data of your request for the households found ​

The search told you who the persons are. To get their households in the format of your request and check that they still meet its eligibility criteria, create an inclusion sub-request on the request detail:

js
await axios.post('BASE_URL/v1/third-app/demande-details/demandeDetail:uuid/extend', {
  include: { searches: [searchUuid] }
});

When it completes, the demande.completed webhook carries the result on the sub-request entry:

json
{ "id": "uuid", "parent_id": "uuid", "type": "DATA_LIST", "status": "COMPLETED",
  "include": { "requested": 2, "eligible": ["0001-00001"], "not_eligible": ["0001-00417"] } }
  • 0001-00001 still meets the criteria: its up-to-date data, with your request's fields, is in Get Data List.
  • 0001-00417 no longer does. If you had already received it through the request, it stays in Get Data List: rely on not_eligible, not on the absence of the code.
